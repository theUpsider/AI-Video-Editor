# Controlled workflow improvement

Treat a repeated failure as an opportunity for one measurable process adjustment, not permission to rewrite the specification.

Record observed evidence, root-cause hypothesis, proposed skill/task/context/test-scheduling change, a fixed and held-out evaluation set, independent review, before/after result, and rollback plan. Keep improvements only when supported by evidence.

Good examples include smaller context bundles, explicit source-time contracts, fewer simultaneous encoders, an independent output oracle, a better handback schema, or a reusable investigation procedure.

Do not weaken acceptance criteria, remove tests, widen tolerances to match buggy output, silence errors, disable security, expand privileges, demote user features, or alter immutable baseline files. Correct a demonstrably faulty oracle only with independent evidence and review.

Keep repository instructions short and remove contradictory obsolete advice. Do not turn this delivery process into a separate orchestration-platform project or an autonomous production self-modification system.
